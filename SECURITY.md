# Security policy

## Supported versions

Security updates are provided for the latest release on the `main` branch.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's private
security-advisory reporting channel and include the affected version, impact, reproduction
steps, and any suggested mitigation. Do not include credentials, customer data, queue
contents, or other sensitive information in reports or examples.

Operationally unsafe or inaccurate model output should normally be reported as a model
safety issue without sensitive data. Treat it as a security vulnerability when it enables
unauthorized access, secret disclosure, code execution, privilege escalation, or a similar
security impact.

No response or remediation deadline is guaranteed. Please allow maintainers reasonable time
to investigate before public disclosure.
